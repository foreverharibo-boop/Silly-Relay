# Silly Relay · 연결 유지 시험판

버전 **0.1.0-test.6** · 별도 서버 플러그인 + 웹 확장 · AGPL-3.0-or-later

아이폰에서 실리태번으로 생성 요청을 보낸 뒤 다른 앱으로 이동해도, 서버가 그 요청을 계속 처리하고, 돌아온 브라우저에 응답을 이어서 전달하도록 만든 시험판입니다. **실리팝 없이 단독으로 사용합니다.** 아이폰 알림 기능은 아직 없습니다.

보관함 없이 연결 유지와 자동 이어받기에 집중합니다. **test.3부터 새로고침 후 원래 채팅으로 답장을 복구합니다.**

## test.6 홈 화면 웹앱 재실행 복구

이전 버전은 브라우저 탭의 실행 번호를 기준으로 대기 중인 답장을 찾았습니다. 페이지 새로고침은 가능했지만, 홈 화면 웹앱을 완전히 종료한 뒤 다시 실행해 실행 번호가 바뀌면 서버가 답장을 받아도 복구 기록을 찾지 못했습니다.

이제 홈 화면에 설치한 웹앱에서는 복구 식별자를 지속 저장합니다. **앱 종료 → 재실행 → 로그인/잠금 해제 → 원래 채팅 열기** 이후에도 새로 보낸 일반 답장을 찾을 수 있도록 수정했습니다. 아이폰과 갤럭시의 홈 화면 웹앱에 적용됩니다. 일반 브라우저의 서로 다른 탭은 계속 분리합니다.

**확장만 test.6으로 업데이트하고 새로고침하세요. 서버 test.3~test.5는 그대로 사용할 수 있습니다.** 이전 답장을 찾는 중에는 서버를 재시작하지 마세요. 서버에 임시로 남은 답장이 사라집니다.

이미 이전 실행에 남은 답장은 원래 채팅에서 **이전 실행 답장 찾기** 버튼으로 확인할 수 있습니다. 홈 화면 웹앱에서만 표시되며 현재 계정·원래 채팅의 후보가 하나이고, 저장된 채팅 내용이 일치하며, 서버에 완료된 응답이 남아 있을 때만 복구합니다. 여러 후보나 수정된 채팅을 임의로 덮어쓰지 않습니다. 닫지 않은 다른 창의 요청을 가져오는 용도로 사용하지 마세요.

서버가 요청을 접수하기 전에 앱을 닫았거나, 사이트 데이터가 삭제됐거나, 서버가 재시작됐거나, 서버 응답 보관 시간(완료 후 1시간)이 지난 경우까지 복구할 수는 없습니다. 이 수정은 자동 검사로 검증했으며 iOS의 실제 강제 종료·암호 화면 재진입은 사용자 기기 재확인이 필요합니다.

## test.5 리즈닝 복구 수정

새로고침 후 답장을 복구할 때 리즈닝 표시를 강제로 켜던 문제를 수정했습니다. `Request Model Reasoning`을 끈 요청은 복구할 때도 생각 내용을 넣지 않습니다. 요청할 때 켜져 있었더라도 복구 시점에 꺼져 있으면 표시하지 않습니다. 이전 버전에서 대기 중이던 요청은 현재 설정을 따릅니다. 답장 본문과 연결 유지 방식은 그대로입니다.

**이번 수정은 Silly Relay 웹 확장만 업데이트한 뒤 페이지를 새로고침하면 적용됩니다.** 확장 버전 `0.1.0-test.5`를 확인해 주세요. 서버 test.3/test.4도 호환되므로 이번 수정 때문에 서버를 재시작할 필요는 없습니다. 이미 채팅에 저장된 생각 내용은 소급해서 삭제하지 않습니다.

## test.4 긴급 수정

복구 준비 오류가 원래 답변 생성까지 중단시키던 경로를 수정했습니다. 생성 직전에 채팅을 다시 강제 저장하고 전체 내용을 읽어 비교하던 과정을 제거했습니다. 복구 연결 정보를 기록하지 못하면 이번 요청은 새로고침 복구 없이 진행한다고 알리고, 기존 서버 연결 유지 요청을 한 번만 보냅니다. 사용자가 누른 생성 중지는 그대로 적용합니다.

복구할 때 원래 채팅인지 확인하는 검사와 채팅 저장 후 응답을 정리하는 검사는 유지합니다. 복구용 이벤트 처리 오류도 실리태번의 일반 생성 흐름으로 전파하지 않습니다.

**서버가 test.3이면 이번 수정은 확장만 업데이트하고 페이지를 새로고침해도 적용됩니다.** 확장 제목에 `0.1.0-test.4`가 표시되는지 확인하세요. 서버 test.3과 test.4 모두 호환됩니다.

## test.3 업데이트

브라우저가 응답 바이트를 받았다고 곧바로 서버 응답을 지우지 않습니다. 원래 채팅 파일에 답장이 저장된 것을 다시 읽어 확인한 뒤 정리합니다. 페이지가 다시 로딩되면 같은 브라우저 탭에서 원래 채팅을 열었을 때 대기 중인 답장을 자동으로 복구합니다. AI를 재호출하지 않습니다.

- **복구 대상:** 1:1 채팅에서 실리태번의 일반 생성 흐름으로 보낸 Chat Completion 일반 답변·재생성. JSON과 SSE 모두 지원합니다.
- 스와이프·계속쓰기·그룹 채팅·다중 후보·도구 호출·숨은 생성·번역/검수 전용 요청은 이번 새로고침 복구 대상이 아닙니다. 기존 연결 유지 기능과 구분됩니다. 요청이 접수되면 설정에 `새로고침 복구 준비됨` 또는 `이 요청은 새로고침 복구 대상 아님`을 표시합니다.
- 다른 채팅에는 붙이지 않습니다. 요청 후 원래 채팅 내용이 바뀌었거나 별도 답장이 추가됐다면 자동 덮어쓰기를 멈추고 알려줍니다. 같은 요청으로 복구된 메시지에는 중복 방지 표식을 남깁니다.
- 새로고침으로 사라진 다른 확장의 검수/재작성 실행 상태까지 복원하지는 않습니다. 복구하는 것은 서버가 받은 생성 답장입니다. 복구 후 일반 메시지 수신 이벤트를 내보내지만, 모든 후처리 확장과의 호환성을 보장하지 않습니다.
- **업데이트 후 새로 보낸 요청부터 적용합니다.** 이전 버전에서 사라진 답장에는 채팅 연결 정보가 없어 소급 복구할 수 없습니다.

기존 GitHub 설치 사용자는 서버가 있는 기기에서 다음 명령으로 서버 플러그인을 업데이트하고, 실리태번 확장 관리에서도 **Silly Relay를 업데이트**한 뒤 서버를 재시작하고 브라우저를 새로고침합니다.

```bash
git -C ~/SillyTavern/plugins/Silly-Relay pull --ff-only
```

PC는 실제 실리태번 설치 폴더의 `plugins/Silly-Relay`에서 `git pull --ff-only`를 실행하면 됩니다. 새 설치는 서버와 확장이 `0.1.0-test.6`으로 표시됩니다. 기존 서버 test.3~test.5도 확장 test.6과 호환됩니다.

## 먼저 알아둘 범위

- **지원 목표:** 서버가 접수한 생성 요청을 브라우저 연결과 분리하고, 같은 페이지로 돌아오면 아직 받지 못한 응답부터 이어받습니다. 일반 JSON 응답과 SSE 스트리밍 응답을 전달합니다.
- **앱 전환·일시적인 통신 단절:** 페이지의 실행 상태가 남아 있으면 원래 생성 흐름으로 이어집니다. 브라우저가 멈춰 있는 동안에도 서버는 응답을 계속 읽습니다.
- **페이지 새로고침·iOS의 페이지 강제 재로드:** 위 복구 대상인 요청은 같은 탭에서 원래 채팅을 열면 답장을 이어받아 저장합니다. 브라우저의 사이트 데이터가 지워진 경우(일반 브라우저는 탭 식별 정보가 지워진 경우도 포함), 서버 재시작 또는 응답 만료 후에는 복구할 수 없습니다. 원래 번역·검수 자바스크립트 실행 상태는 복원하지 않습니다.
- **번역·검수 등 다른 확장:** 이미 아래의 실리태번 생성 API로 보낸 요청은 대상이 됩니다. 아직 브라우저에서 준비 중인 요청, 다음 검수/재생성 단계, 외부 서버로 직접 보내는 요청까지 대신 실행하지는 않습니다. 모든 확장 조합의 호환성을 검증한 상태가 아닙니다.
- **중지 버튼:** 실리의 생성 중지를 누르면 서버에도 취소를 보냅니다. 오프라인이라 전달하지 못하면 복귀 후 다시 보냅니다. 그동안 AI 요청은 진행될 수 있습니다.
- **서버 자체는 계속 켜져 있어야 합니다.** 서버 종료·절전·AI 제공업체 오류까지 방지하는 기능은 아닙니다.

따라서 이 버전은 “아이폰에서 무엇을 하든 절대 끊기지 않는 완성판”이 아니라, **생성 요청을 서버가 유지하는 방식의 실제 기기 검증용**입니다. 아이폰 8 / iOS 15에서 실행 여부와 복귀 동작은 아직 실기기 확인 전입니다. 이 시험에는 iOS 웹 푸시나 HTTPS 설치형 웹앱이 필요하지 않습니다.

## 설치

서버 플러그인은 **실리태번 서버가 실행되는 갤럭시 Termux 또는 PC**에 설치합니다. 아이폰에는 APK를 설치하지 않습니다.

### GitHub에서 설치하기 (권장)

**1. 서버가 켜져 있는 갤럭시의 Termux에서 새 세션을 엽니다.** 서버 로그가 올라오는 화면에 입력하지 말고 새 셸에서 실행해 주세요.

```bash
cd ~/SillyTavern
node plugins.js install https://github.com/foreverharibo-boop/Silly-Relay
```

실리태번을 다른 경로에 설치했다면 첫 줄만 실제 경로로 바꿔 주세요.

**2. 실제 사용하는 `config.yaml`에서 기존 `enableServerPlugins` 항목이 `true`인지 확인합니다.** 이미 실리팝 등 서버 플러그인이 작동 중이라면 켜져 있을 수 있습니다. 아래는 확인만 하는 명령입니다.

```bash
grep -n '^enableServerPlugins:' ~/SillyTavern/config.yaml
```

`false`라면 `nano ~/SillyTavern/config.yaml`로 열어 그 값을 `true`로 바꾸고 저장합니다. 같은 항목을 맨 아래에 추가하지 마세요.

**3. 기존 실리 서버를 완전히 종료하고 평소 방법으로 다시 실행합니다.** 시작 로그에 `[Silly Relay] 0.1.0-test.6 loaded`가 나오면 서버 플러그인이 로딩된 것입니다. 브라우저만 닫았다 여는 것으로는 적용되지 않습니다.

**4. 아이폰에서 평소 쓰는 주소로 같은 실리태번 서버에 접속합니다.** 실리책방에 접속했던 서버와 같은 서버이며, 실리태번 본화면을 열면 됩니다. 서버 폰과 아이폰의 기존 Tailscale 연결도 켜 두세요.

**5. 실리태번의 확장 메뉴 → 확장 설치에서 다음 주소를 넣습니다.** 아이폰에서 사용하는 실리태번 계정에 설치하면 됩니다.

```text
https://github.com/foreverharibo-boop/Silly-Relay
```

**6. 실리 페이지를 새로고침한 뒤 확장 설정의 `Silly Relay · 연결 유지 시험판`을 엽니다.** `연결 확인`을 눌러 `서버 0.1.0-test.6 연결됨`을 확인하고 `연결 유지 시험 기능`을 켭니다. 이 스위치는 현재 브라우저에만 적용되므로 아이폰에서 켜 주세요.

**7. 아래 아이폰 테스트 순서로 확인합니다.** APK 설치나 실리팝 연결 키 입력은 필요하지 않습니다.

ZIP 시험판을 이미 수동 설치했다면 같은 이름의 폴더가 있어 GitHub 설치가 거절될 수 있습니다. 그 경우 기존 폴더를 임의로 덮어쓰거나 삭제하지 말고 설치 결과를 알려 주세요.

### ZIP으로 설치하기 (대안)

압축 파일을 서버 폰의 Download 폴더에 받은 뒤, Termux 새 세션에서 실행합니다. 저장소 접근 권한을 아직 허용하지 않았다면 먼저 `termux-setup-storage`를 실행하고 권한을 허용해 주세요.

```bash
pkg install unzip
unzip -n ~/storage/downloads/Silly-Relay-v0.1.0-test.4.zip -d ~/silly-relay-test
bash ~/silly-relay-test/silly-relay/install.sh ~/SillyTavern
```

계정을 여러 개 쓰고 있어 사용자를 자동으로 고르지 못하면 마지막 명령에 사용자 핸들을 붙입니다. 예:

```bash
bash ~/silly-relay-test/silly-relay/install.sh ~/SillyTavern default-user
```

설치 스크립트는 기존 `Silly-Relay` 폴더가 있으면 덮어쓰지 않고 중단합니다. 다른 플러그인, 실리팝, 채팅 파일, 설정 파일은 수정하지 않습니다. 사용자 데이터 경로를 별도로 바꾼 설치는 아래 수동 설치 방식을 사용해 주세요.

### PC / 수동 설치

1. 실리태번의 `plugins/Silly-Relay` 폴더를 새로 만들고, 압축 안의 `package.json`, `LICENSE`, `server` 폴더를 넣습니다.
2. **접속할 실리태번 계정**의 `data/<사용자핸들>/extensions/Silly-Relay` 폴더를 새로 만들고 `manifest.json`, `index.js`, `transport.mjs`, `recovery.mjs`, `style.css`, `LICENSE`를 넣습니다.
3. 실제 사용하는 `config.yaml`의 기존 항목이 `enableServerPlugins: true`인지 확인합니다.
4. 실리태번 서버를 완전히 종료한 뒤 다시 시작합니다. 로그의 `[Silly Relay] 0.1.0-test.6 loaded`를 확인합니다.
5. 아이폰에서 평소 쓰던 주소로 같은 실리 서버에 접속한 뒤 페이지를 새로고침합니다.
6. 확장 설정의 **Silly Relay → 연결 확인**을 눌러 서버 연결을 확인하고 **연결 유지 시험 기능**을 켭니다. 켜짐 상태는 그 브라우저에만 저장됩니다.

실리태번 자체에 TLS 인증서를 설정해 HTTPS로 직접 실행하는 구성은 이번 시험판에서 지원하지 않습니다. HTTP 실리 서버에 접속하거나, HTTPS 프록시가 앞에 있고 실리 서버 자체는 HTTP로 실행되는 구성을 대상으로 합니다. 인증이나 HTTPS 보호를 끄라는 뜻은 아닙니다.

## 아이폰에서 해 볼 테스트

1. 평소처럼 답변 하나를 요청합니다. 가능하면 처음에는 일반 답변으로 해 주세요.
2. 확장 상태에 **서버에서 생성 중**이 표시되거나 스트리밍 글자가 나오기 시작하면 다른 앱으로 나갑니다.
3. 아이폰에서 실리를 다시 열기 전에 서버 폰/PC 로그에 `[Silly Relay] ... completed`가 찍히는지 확인합니다.
4. 실리로 돌아왔을 때 답변이 이어서 표시되는지 확인합니다.
5. 페이지가 처음부터 로딩됐다면 원래 채팅을 열고 잠시 기다립니다. `새로고침 전에 받던 답장을 원래 채팅에 복구했어요.` 알림과 함께 답장이 한 번만 붙는지 확인합니다. 새 답변을 다시 요청할 필요는 없습니다. 처음 테스트에서는 접수 상태의 `새로고침 복구 준비됨` 표시를 확인해 주세요.

실제 AI 생성 테스트는 평소 사용 중인 API의 요금이 적용됩니다. 이 플러그인이 재연결 때문에 AI를 다시 호출하지 않도록 작업 번호로 중복 접수를 막았습니다. 타임아웃이나 오류가 발생해도 자동으로 일반 생성 요청을 하나 더 보내지 않습니다.

## 임시 전송 버퍼·인증

- 기존 실리태번 로그인과 CSRF 검사를 그대로 사용하며, 서버 내부 요청에도 인증을 다시 적용합니다. 결과는 요청한 실리태번 사용자별로 분리합니다.
- **보관함·응답 목록·다시 보기 기능은 없습니다.** 브라우저가 멈춘 동안 아직 전달하지 못한 응답만 서버 메모리의 임시 전송 버퍼에 둡니다. 복구 대상 요청은 채팅 저장을 확인한 뒤 최종 수신 확인을 보내고, 서버는 그때 응답 본문을 삭제합니다. 복구 대상이 아닌 요청은 전송 완료 시 수신 확인을 보냅니다. 오류·취소 시에도 본문을 삭제합니다.
- 브라우저가 돌아오지 않거나 수신 확인 전송이 실패하면, 미확인 응답은 완료 후 최대 약 1시간 뒤 자동 정리됩니다(1분 간격 검사). 서버를 재시작해도 사라집니다. 중복 AI 호출을 막기 위한 요청 번호·해시·상태는 본문 삭제 후에도 만료 시점까지 남습니다.
- 복구용으로 브라우저에는 요청 번호·사용자별 구분·탭 번호·원래 채팅 식별 정보·변경 감지용 지문 등 작은 연결 정보를 기록합니다. API 키나 프롬프트·응답 본문은 이 기록에 넣지 않습니다. 응답 본문은 서버 메모리에서 대기하다가 원래 실리태번 채팅에 저장됩니다. 외부 중계 서버나 별도 응답 보관 파일은 만들지 않습니다.
- 최대 생성 시간 20분, 요청/응답 각각 8 MiB, 총 임시 버퍼 64 MiB, 동시 요청 사용자당 4개·서버 전체 8개로 제한합니다. 이를 넘으면 오류를 표시합니다.
- 기본적인 쿠키 로그인·Basic 인증 전달을 구현했습니다. 특수한 인증 프록시 구성은 별도 확인이 필요합니다.

## 사용 중지 / 제거

확장 설정에서 **연결 유지 시험 기능**을 끄면 새 요청부터 원래 방식으로 돌아갑니다. 이미 진행 중인 요청을 취소하려면 실리태번의 생성 중지 버튼을 누릅니다.

제거할 때는 생성이 끝난 뒤 서버를 종료하고, 이번에 만든 `plugins/Silly-Relay`와 `data/<사용자핸들>/extensions/Silly-Relay` 두 폴더만 제거한 다음 서버를 재시작합니다.

## 검증 결과와 한계

`npm test`는 별도 패키지 설치 없이 Node.js에서 실행됩니다. 실제 HTTP 서버와 브라우저용 전송 모듈을 연결해 JSON/SSE, 네트워크 단절, 접수 응답 유실, 중복 방지, 중지, 사용자 분리, 크기 제한, 임시 버퍼 만료, 수신 확인 뒤 응답 삭제, 새 페이지에서의 JSON/SSE 복구, 저장 실패 후 재시도, 중복/다른 채팅 덮어쓰기 방지를 검사합니다. 테스트는 가짜 AI 응답을 사용하므로 비용이 없습니다.

**실제 아이폰·사용 중인 실리태번 설치·다른 확장 조합에서의 검증은 아직 남아 있습니다.** 테스트 서버가 실리태번의 전체 기능을 대체하는 것은 아닙니다. 공개 정식 배포 전 시험판입니다.

관찰한 실리태번 `release` 소스는 `src/endpoints/backends/chat-completions.js`(Git blob `0d98c77f7b64502c5b0f504eaa1f67df0f26041e`)에서 클라이언트 소켓 종료 시 AI 요청을 취소하고 있습니다. 본 시험판은 해당 원본 파일을 수정하지 않고 별도 서버 연결로 요청을 유지합니다.
