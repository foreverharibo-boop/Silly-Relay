# Silly Relay

**웹 확장 1.0.8 / 서버 플러그인 1.0.2 · 정식 배포 · AGPL-3.0-or-later**

실리에서 답장을 기다리는 동안 다른 앱을 봐도, 서버가 이미 접수한 AI 응답을 끝까지 받아 줍니다. 페이지가 다시 열리면 원래 채팅에 답장을 복구합니다. 아이폰과 갤럭시에서 사용할 수 있고, 실리태번 원본 파일을 수정하지 않습니다.

**[Silly-Pop iOS](https://github.com/foreverharibo-boop/Silly-Pop/tree/ios)**와 함께 쓰면 아이폰 알림도 받을 수 있습니다. 릴레이 단독으로는 알림을 보내지 않습니다. 갤럭시 Silly-Pop과도 함께 사용할 수 있습니다.

## 지원하는 것

- 실리태번의 최종 생성 이벤트로 확인한 일반 답장·재생성·스와이프·계속쓰기 요청의 JSON/SSE 수신을 브라우저 연결과 분리합니다.
- 명시적으로 연동된 답장 재작성을 제외한 숨은 생성(quiet)·번역·검수·기억 수집 및 답장으로 확인하지 못한 요청은 원래 전송 경로를 그대로 사용합니다. 이런 요청은 릴레이의 동시 생성·응답 보관 자리를 차지하지 않습니다. 요청을 차단하거나 AI를 추가 호출하지 않습니다.
- **또또 1.13.18 및 100LOG 1.9.31의 답장 검수**와 연동하면 초안과 실제 답장 재작성을 하나로 묶어 마지막 수정본을 복구합니다. 두 확장을 함께 써도 같은 답장의 수정본으로 관리합니다. Jev 판정·기억 수집 등 보조 요청은 각 확장에서 원래대로 실행하며 릴레이 보관 대상에서는 제외합니다.
- **1:1 Chat Completion의 일반 답장·재생성·새 스와이프**는 새로고침하거나 홈 화면 웹앱을 껐다 켠 뒤 원래 채팅에서 복구합니다.
- 스와이프 복구는 이전 후보와 후보별 번역·정보를 유지하고 새 후보 하나를 추가합니다. 이번 요청의 일부가 저장됐다면 그 자리만 완성합니다.
- 이미 저장한 답장을 중복 추가하지 않고, 재접속 때문에 AI 요청을 다시 보내지 않습니다. 복구할 위치가 수정됐거나 다른 답장이 추가됐다면 자동 덮어쓰기를 중단합니다.
- 리즈닝 표시 설정을 따르며, 꺼둔 생각 내용을 복구하면서 강제로 표시하지 않습니다.

계속쓰기·그룹 채팅·다중 후보·도구 호출·미연동 숨은 생성·번역/검수 전용 요청은 새로고침 복구 대상이 아닙니다. 새로고침으로 사라진 다른 확장의 자바스크립트 실행 상태나 다음 검수·번역 단계를 대신 실행하지도 않습니다. 모든 확장 조합과 호환되는 것은 아닙니다.

**서버는 계속 켜져 있어야 합니다.** 서버 접수 전에 앱을 종료하거나, 서버를 재시작하거나, 사이트 데이터를 지우거나, 완료 후 임시 응답이 만료되면 복구할 수 없습니다. 홈 화면 웹앱은 재실행 식별자를 유지하고, 일반 브라우저는 같은 탭의 식별 정보를 사용합니다.

## 설치

서버 플러그인은 **실리태번 서버가 실행되는 갤럭시 Termux 또는 PC**에 설치합니다. 아이폰에 APK를 설치하는 방식이 아닙니다.

### 1. 서버 플러그인

Termux의 새 셸에서 실행합니다. 실리 설치 경로가 다르면 첫 줄만 바꾸세요.

```bash
cd ~/SillyTavern
node plugins.js install https://github.com/foreverharibo-boop/Silly-Relay
```

실제 사용하는 `config.yaml`의 기존 `enableServerPlugins`가 `true`인지 확인합니다. 같은 항목을 맨 아래에 추가하지 마세요. 이미 다른 서버 플러그인이 작동한다면 그대로 두면 됩니다.

진행 중이거나 복구할 답장을 먼저 받은 뒤 서버를 완전히 종료하고 평소 방법으로 다시 켭니다. `[Silly Relay] 1.0.2 loaded`가 보이면 로딩된 것입니다. 브라우저만 새로고침하는 것으로는 서버 업데이트가 적용되지 않습니다.

### 2. 웹 확장

아이폰/갤럭시에서 사용하는 실리태번 계정의 **확장 메뉴 → 확장 설치**에 아래 주소를 넣습니다.

```text
https://github.com/foreverharibo-boop/Silly-Relay
```

실리 페이지를 새로고침한 뒤 **Silly Relay → 연결 확인 → 연결 유지**를 켭니다. 스위치는 현재 브라우저에 적용되므로 실제 채팅하는 아이폰 웹앱에서도 켜 주세요.

서버와 아이폰이 떨어져 있다면 기존 Tailscale 등 실리 접속 방법을 그대로 사용합니다. SillyTavern 자체 HTTPS 모드는 지원하지 않습니다. HTTP 서버 또는 HTTPS 프록시 뒤의 HTTP 서버를 대상으로 하며, 인증·HTTPS 보호를 끄라는 뜻은 아닙니다.

### PC / 수동 설치

PC에서도 서버가 있는 실제 실리 폴더에서 같은 `node plugins.js install` 명령을 실행하고, 웹 확장은 위 주소로 설치합니다.

수동 설치는 저장소의 `package.json`, `LICENSE`, `server`를 `plugins/Silly-Relay`에, `manifest.json`, `index.js`, `transport.mjs`, `recovery.mjs`, `identity.mjs`, `reply-filter.mjs`, `reply-session.mjs`, `style.css`, `LICENSE`를 실제 사용자 `data/<사용자핸들>/extensions/Silly-Relay`에 넣습니다. 기존 폴더가 있다면 임의로 덮어쓰지 말고 설치 방식부터 확인하세요. 저장소에 포함된 `install.sh`는 기본 data 경로의 새 설치용이며 기존 폴더를 덮어쓰지 않습니다.

## 기존 버전에서 업데이트

### 10월 10일 · 웹 확장 1.0.8 / 100LOG 1.9.31 연동

100LOG가 받은 답장을 실제로 재작성할 때도 같은 답장의 복구 기록에 연결합니다. 또또가 먼저 수정한 뒤 100LOG가 다시 수정하면 마지막 수정본을 복구합니다. 검수 판정이나 기억 수집 결과가 캐릭터 답장으로 표시되지는 않습니다.

수정 요청이 진행 중이면 그 요청이 끝날 때까지 기다리며, 실패하면 앞서 받은 정상 답장을 보존합니다. 검수 전에 저장된 초안 때문에 수정본이 먼저 정리되지 않도록 했습니다. 중지·채팅 변경·수동 편집 뒤 늦게 온 수정본은 자동으로 덮어쓰지 않습니다.

**확장 관리에서 Silly Relay 1.0.8과 100LOG 1.9.31을 모두 업데이트하고, 진행 중인 답장 처리가 끝나면 실리 페이지를 새로고침합니다.** 또또를 함께 쓰면 1.13.18 이상을 사용합니다. 서버 플러그인은 1.0.2 그대로이며 이번 업데이트에 서버 명령어나 재시작은 필요 없습니다.

복구하는 것은 서버가 이미 접수한 답장 요청입니다. 브라우저를 종료하면 아직 시작하지 않은 다음 검수·재작성 단계까지 대신 실행하지는 않습니다.

### 10월 10일 · 웹 확장 1.0.7 / 또또 1.13.18 연동

또또의 표시 전 검수에서 실제 답장을 수정하는 요청을 릴레이에 연결했습니다. 초안 → 수정 1회 → 수정 2회를 별도 답장으로 복구하지 않고 하나의 답장으로 관리하며, **가장 최근에 정상 수신한 완전한 본문**을 표시합니다. 새 수정 요청이 서버에서 진행 중이면 완료를 기다립니다. 수정 요청이 실패하거나 빈 응답이면 직전의 정상 답장을 보존하고, 또또가 이미 최종 응답을 선택했다면 그 선택을 따릅니다. Jev 판정·기억 수집·번역 등 보조 요청은 릴레이로 보내지 않습니다.

**실리태번 확장 관리에서 Silly Relay 1.0.7과 또또 1.13.18을 모두 업데이트한 뒤, 답장 처리가 끝난 상태에서 페이지를 새로고침합니다.** 서버 플러그인은 1.0.2 그대로입니다. 이번 업데이트에 서버 명령어나 서버 재시작은 필요 없습니다.

이 연동은 1:1 Chat Completion의 일반 답장·재생성·스와이프를 대상으로 합니다. 다른 검수 확장의 재작성은 자동으로 포함하지 않습니다. 페이지가 종료되면 브라우저의 검수 코드도 멈춥니다. 릴레이는 **이미 서버에 접수된 수정 요청**을 끝까지 받아 복구하며, 아직 보내지 않은 다음 수정·검수 단계를 대신 실행하지 않습니다. 따라서 검수 도중 완전히 재시작했다면 마지막으로 받은 답장은 복구해도 모든 검수 단계가 끝났다는 뜻은 아닙니다.

JSON/SSE 최종 수정본 복구, 작성 중 대기, 실패 시 직전 답장 보존, 스와이프 후보 보존, 중복 방지와 저장 확인 후 모든 초안 버퍼 정리를 자동 검사했습니다. 실제 사용자 기기에서의 확인은 별도입니다.

### 10월 10일 · 웹 확장 1.0.6 (이전 기록)

생성 API 주소만 보고 보조 요청까지 릴레이가 맡던 동작을 수정했습니다. 이제 실리태번의 생성 종류와 최종 요청 데이터를 연결해 확인한 답장만 릴레이로 보냅니다. 같은 생성 중에 발생한 보조 요청이 답장 요청이나 복구 기록을 대신 차지하지 않도록 합니다. 답장 데이터의 연결을 확인하지 못하면 원래 요청을 그대로 전송합니다. 같은 한도 경고는 30초 안에 반복해서 띄우지 않으며, 마지막 오류는 설정에 계속 표시합니다.

**실리태번 확장 관리에서 Silly Relay를 1.0.6으로 업데이트하고 페이지를 새로고침합니다.** 서버 플러그인은 1.0.2 그대로이며, 이번 수정에 서버 플러그인 업데이트는 필요 없습니다. 새로고침 복구 대상(1:1 일반 답장·재생성·스와이프)과 채팅 저장 확인 후 임시 응답을 정리하는 방식은 유지합니다. 계속쓰기의 연결 유지는 지원하지만 새로고침 복구는 지원하지 않습니다. 1.0.6에서는 quiet 재작성을 보호하지 않았으며, 1.0.7부터 위 또또 연동을 지원합니다. 명시적으로 연동하지 않은 재작성은 여전히 원래 경로를 사용합니다.

이전 버전이 이미 접수한 요청은 업데이트만으로 취소되지 않습니다. 아직 받거나 복구할 답장이 없는 상태에서 서버를 한 번 재시작하면 남은 임시 작업이 정리됩니다. 서버를 재시작하면 아직 저장하지 못한 임시 응답도 사라지므로 답장을 먼저 확인합니다.

### 이전 업데이트

1.0.5부터 채팅 진입·새로고침 시 예전 복구 요청의 응답이 서버에 없는 경우(HTTP 404/410)는 노란 토스트 대신 확장 설정의 **최근 복구 확인**과 브라우저 콘솔에 기록합니다. 새 답장의 생성 실패라는 뜻은 아닙니다. 직접 **답장 복구 확인**을 누른 경우는 안내를 표시하고, 실제 생성 오류와 복구 충돌 경고는 유지합니다.

**이미 웹 확장 1.0.3 또는 1.0.4 / 서버 1.0.2를 사용 중이면**, 실리 확장 관리에서 Silly Relay를 **1.0.5**로 업데이트하고 실리 페이지를 새로고침하세요. 이번 수정에 서버 재시작은 필요 없습니다. 답장 본문·원래 기록·위치가 서버 보관 응답과 일치하고 화면과 채팅 파일에 모두 있는 경우, 완료 표시가 없어도 재복구하지 않고 대기 기록만 정리합니다. 실제 수정이나 다른 답장을 덮어쓰지 않는 검사는 유지합니다.

### 그 이전 버전에서 업데이트

**웹 확장 1.0.5 / 서버 플러그인 1.0.2**로 함께 업데이트합니다. 오류 응답을 전달한 뒤에도 보관 자리를 차지하던 경로를 정리하고, 생성 종류가 없는 보조 요청이 메인 답장의 복구 기록을 차지하지 않도록 수정했습니다. 정상 답장은 기존처럼 채팅 저장을 확인한 뒤에만 임시 보관에서 지웁니다.

서버는 이제 동시 생성 한도와 전달·저장 확인 대기 한도를 구분해서 표시합니다. 한도 자체를 늘리거나 복구 대기 답장을 강제로 삭제하지는 않습니다. 이번 업데이트는 **서버 플러그인 업데이트·서버 재시작과 웹 확장 업데이트**가 모두 필요합니다.

**진행 중이거나 아직 복구할 답장을 먼저 받은 뒤** 서버를 종료하세요. 재시작하면 서버의 임시 답장은 사라집니다. 아래 명령으로 서버 플러그인을 업데이트한 다음 서버를 다시 켜고, 실리 확장 관리에서 Silly Relay도 업데이트한 뒤 실리 페이지를 새로고침합니다.

```bash
git -C ~/SillyTavern/plugins/Silly-Relay pull --ff-only
```

실리태번 확장 관리에서도 **Silly Relay를 업데이트**한 다음 서버를 재시작하고 실리 페이지를 새로고침합니다. 서버 test.3 이상과도 호환되므로 버전 차이만으로 기존 동작이 중단되지는 않습니다. 정식 배포 상태로 맞추려면 양쪽 모두 업데이트하세요. 수동 설치본은 위 Git 명령 대신 자신의 설치 방식으로 파일을 업데이트합니다.

## 사용 확인

1. 일반 답장이나 새 스와이프를 요청합니다.
2. 설정에 **서버에서 생성 중·새로고침 복구 준비됨**이 표시된 뒤 홈 화면이나 다른 앱으로 이동합니다.
3. 서버 로그의 `[Silly Relay] ... completed (HTTP 200, ... bytes)`는 응답 수신 종료를 뜻합니다. HTTP 403/429/500 등이라면 오류 응답을 받은 것이므로 생성 성공으로 보지 마세요.
4. 실리로 돌아옵니다. 페이지가 다시 로딩됐다면 원래 채팅을 열고 잠시 기다립니다. 필요한 경우 홈 화면 웹앱의 **답장 복구 확인**을 누릅니다.
5. 답장이 한 번만 표시되고 기존 스와이프 후보도 남는지 확인합니다. 답장을 찾으려고 새 생성을 다시 요청할 필요는 없습니다.

실제 답장 생성에는 평소 AI API 요금이 적용됩니다. 릴레이의 재연결·복구 자체는 AI를 다시 호출하지 않습니다. 중지 버튼을 누르면 서버에도 취소를 보내지만, 오프라인이라 전송하지 못한 동안에는 AI 요청이 진행될 수 있습니다.

## 임시 응답과 인증

- 기존 실리태번 로그인·CSRF 보호를 사용하며, 서버 내부 요청에도 인증을 적용합니다. 결과는 요청한 사용자 계정별로 구분합니다.
- 아직 전달하지 못한 응답은 **서버 메모리**에 임시로 둡니다. 복구 대상은 채팅 파일에 저장된 것을 확인한 뒤 응답 본문을 지웁니다. 오류·취소 시에도 삭제합니다. 외부 중계 서버나 별도 응답 보관 파일은 만들지 않습니다.
- 돌아오지 않거나 수신 확인에 실패하면 미확인 응답은 완료 후 최대 약 1시간 뒤 정리됩니다. 서버 재시작 시에도 사라집니다.
- 브라우저에는 요청 번호·채팅 식별 정보·변경 확인용 지문 등 작은 복구 정보를 남기며, 이 기록에 API 키·프롬프트·답장 본문은 넣지 않습니다.
- 최대 생성 시간 20분, 요청/응답 각각 8 MiB, 임시 버퍼 총 64 MiB, 동시 요청 사용자당 4개·서버 전체 8개입니다.
- 로그인 없이 계정 하나를 공동 사용하는 경우 그 계정 안의 사용자를 따로 구분하지 않습니다. 특수한 인증 프록시 구성은 별도 확인이 필요합니다.

## 끄기 / 제거

**연결 유지**를 끄면 새 요청부터 원래 방식으로 돌아갑니다. 이미 진행 중인 요청은 실리의 생성 중지 버튼으로 취소합니다.

제거하려면 답장 처리가 끝난 뒤 서버를 종료하고, 이 앱의 `plugins/Silly-Relay`와 해당 계정의 `extensions/Silly-Relay` 폴더만 제거한 다음 서버를 다시 켭니다.
